1. Visión General del Proyecto

Descripción, objetivos y alcance del sistema

ST Ventas es un sistema de gestión de punto de venta (POS) y administración de inventario desarrollado como aplicación web con arquitectura desacoplada: una API REST en Laravel 12 (PHP 8.2) y una SPA en React 19. Permite registrar ventas, gestionar inventario, controlar compras a proveedores y generar reportes, con autenticación JWT, control de acceso por roles y auditoría automática de todos los cambios.

Objetivos Principales

  • POS ágil con carrito + confirmación de pago
  • Control de stock con alertas de nivel mínimo
  • Gestión de compras con flujo de estados
  • Dashboard con KPIs y gráficos en tiempo real
  • Auditoría completa de operaciones
  • Control de acceso por roles (super-admin / admin / vendedor)

Características Técnicas Destacadas

  • Patrón Init Endpoint — 1 HTTP para cargar múltiples catálogos
  • Caché Redis versionado con invalidación automática
  • Trait Auditable — log automático en todos los modelos
  • JWT con Rate Limiter en login
  • Transacciones de BD para ventas y compras
  • Columna storedAs en detalle_venta/compra

cd backend
composer install
cp .env.example .env
php artisan key:generate
php artisan jwt:secret
php artisan migrate --seed        # Crea tablas + roles + usuarios de prueba

php artisan serve                 # Puerto 8000

# 2. Frontend
cd ../frontend
npm install
npm run dev                       # Puerto 5173 (Vite)

Capas, patrones y traits del servidor

No se usa capa de Service ni Repository intencionalmente: la lógica de negocio vive directamente en los controladores (thin controller con excepciones — los controladores de ventas y compras sí son gruesos por la lógica de stocks y transacciones).

Trait ApiResponse

Todos los controladores heredan de App\Http\Controllers\Controller que usa el trait ApiResponse. Esto estandariza el formato de respuesta en toda la API.

// Éxito:
return $this->success($data, 'Mensaje', 200, $meta);
// → { "status": true, "message": "Mensaje", "data": {...}, "meta": {...} }

// Error:
return $this->error('Error de stock.', 422, $erroresStock);
// → { "status": false, "message": "Error de stock.", "errors": [...] }

Form Requests — Validación

Cada operación de escritura tiene su propio Form Request con reglas y mensajes en español. La validación fallida retorna automáticamente HTTP 422 con los errores en el campo errors.

API Resources — Transformación JSON

Cada modelo tiene su Resource que transforma los datos antes de devolverlos al cliente, evitando exponer campos internos (como contrasena, remember_token, deleted_at).

// Ejemplo: ProductoResource
class ProductoResource extends JsonResource {
    public function toArray($request): array {
        return [
            'id'            => $this->id,
            'codigo'        => $this->codigo,
            'nombre'        => $this->nombre,
            'precio_venta'  => (float) $this->precio_venta,
            'stock'         => $this->stock,
            'activo'        => $this->activo,
            'categoria'     => new CategoriaResource($this->whenLoaded('categoria')),
        ];
    }
}

7. Sistema de Autenticación JWT

Flujo completo: login → token → request protegido → logout

Configuración JWT

Se usa tymon/jwt-auth. El guard api está configurado en config/auth.php con el driver jwt y el provider usuarios.

// config/auth.php (extracto)
'guards' => [
    'api' => [
        'driver'   => 'jwt',
        'provider' => 'usuarios',
    ],
],
'providers' => [
    'usuarios' => [
        'driver' => 'eloquent',
        'model'  => App\Models\Usuario::class,
    ],
],

Modelo Usuario — Interfaz JWTSubject

class Usuario extends Authenticatable implements JWTSubject {
    // Claims adicionales incluidos en el payload del token:
    public function getJWTCustomClaims(): array {
        return [
            'id'      => $this->id,
            'nombre'  => $this->nombre . ' ' . $this->apellido,
            'usuario' => $this->usuario,
        ];
    }
    // JWT usa 'password' internamente; nuestro campo se llama 'contrasena':
    public function getAuthPassword(): string {
        return $this->contrasena;
    }
}

Protección de Rutas API

// routes/api.php — grupo protegido
Route::middleware(['auth:api', 'cache.api'])->group(function() {
    Route::apiResource('productos', ProductoController::class);
    Route::get('pos/init', [PosController::class, 'init']);
    // ...
});

// Solo super-admin:
Route::middleware(['auth:api', 'role:super-admin'])->group(function() {
    Route::get('auditoria', [AuditoriaController::class, 'index']);
    Route::apiResource('configuracion', ConfiguracionController::class);
});
