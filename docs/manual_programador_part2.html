Invalidación Automática con HasApiCache

// El trait se adjunta al modelo:
class Producto extends Model {
    use HasApiCache;

    // Invalida 2 módulos al guardar o eliminar:
    protected array $cacheModules = ['productos', 'dashboard'];
}

// El trait registra eventos boot automáticamente:
static::saved($bumpVersion);     // cubre created + updated
static::deleted($bumpVersion);

// bumpVersion incrementa el contador Redis:
Cache::increment("cache_ver:productos");  // v3 → v4
// Todas las claves antiguas quedan huérfanas y expiran por TTL.

Invalidación Manual desde Controlador

// Cuando decrement/increment no dispara eventos Eloquent:
$this->decrement('stock', $cantidad);
$this->invalidateCache(['productos', 'dashboard']);

10. Sistema de Auditoría

Trait Auditable + tabla auditoria_logs

Cualquier modelo que use el trait Auditable registra automáticamente en auditoria_logs cada operación de creación, actualización y eliminación, incluyendo los valores anteriores y nuevos.

// Adjuntar a un modelo:
class Venta extends Model {
    use Auditable, HasApiCache;
}

// El trait registra estos eventos:
static::created  → accion = 'created',  valores_nuevos = toArray()
static::updated  → accion = 'updated',  valores_anteriores = getOriginal(), valores_nuevos = getChanges()
static::deleted  → accion = 'deleted',  valores_anteriores = toArray()

// Campos ocultos del modelo ($hidden) se excluyen del log automáticamente.
// Si falla la auditoría, la operación principal NO se bloquea (try/catch).

function PrivateRoute({ children }) {
  const { isAuthenticated } = useAuth();

function AdminRoute({ children }) {
  const { isAuthenticated, isAdmin } = useAuth();
  if (!isAuthenticated) return <Navigate to="/login" replace />;

Por Qué Context en lugar de Zustand

✅ Ventajas del enfoque actual

  • Sin dependencia externa — React lo provee de serie
  • El auth cambia pocas veces: login/logout/updateUser
  • Código más explícito con actions tipadas (switch reducer)
  • Easier testing — Provider envuelve el árbol directamente

⚠️ Consideraciones

  • Context no tiene selectores — todos los consumidores re-renderizan
  • Para estado de alta frecuencia (carrito POS), se usa useState local
  • Si el proyecto crece mucho, considerar Zustand o Redux Toolkit

Lectura del Token desde Fuera de React (api.js)

// api.js — los interceptores Axios no pueden usar useContext()
function getToken() {
  try {
    const raw = localStorage.getItem('auth-storage');
    if (!raw) return null;
    const data = JSON.parse(raw);
    // Compat. con formato antiguo Zustand: { state: { token }, version }
    return (data.state ?? data)?.token ?? null;
  } catch { return null; }
}
// Se llama en el interceptor request:
// config.headers.Authorization = `Bearer ${token}`

16. Patrones y Decisiones Técnicas

Por qué el código es como es

Patrón / DecisiónRazón
Init Endpoint — un GET agrupa N catálogosReduce N round-trips a 1. Con Redis + JWT, cada petición extra cuesta ~5ms mínimo. En conexiones móviles o lentas el ahorro es notable en percepción de velocidad.
storedAs en subtotalGarantía de integridad matemática en BD. No depende de PHP para el cálculo. Si alguien actualiza cantidad directamente via SQL, el subtotal sigue siendo correcto.
Caché versionada (no flush)Incrementar una versión es O(1) vs. iterar y borrar todas las claves que empiezan por "productos:*". No requiere SCAN en Redis. Las claves huérfanas expiran solas por TTL.
Trait en lugar de BaseModel para cachéComposición > herencia. No todos los modelos necesitan caché. Cada uno declara sus $cacheModules independientemente.
Context + useReducer en lugar de ZustandEl estado de auth cambia 2-3 veces por sesión. No justifica una librería externa. El overhead de Context (re-render) es insignificante para auth.
Estado local en POSEl carrito es efímero — vive y muere con el componente. Ponerlo en Context global causaría re-renders innecesarios en otros módulos.
getToken() leyendo localStorage directamenteLos interceptores de Axios se ejecutan fuera del árbol React. No pueden usar useContext(). LocalStorage es la única solución sin introducir un singleton de estado (que rompería SSR).
SoftDeletes en usuarios y productosPermite auditabilidad completa. Un usuario "eliminado" sigue referenciado en ventas históricas sin romper FKs.
Rate Limiter en login (5 intentos)Protección bruta contra ataques de fuerza bruta sin necesitar CAPTCHA. El decay es por IP, no por usuario, para evitar DoS contra cuentas específicas.
PostgreSQL como único driver soportadoSe usan características específicas: ILIKE, jsonb, storedAs con expresiones, NOW() - INTERVAL. Migrar a MySQL requeriría reescribir estas queries.
