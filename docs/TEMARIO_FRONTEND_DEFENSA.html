1 · Componentes y Hooks Fundamentales
P1.¿Cuándo se usa useEffect y cuál es el riesgo de no declarar sus dependencias?

useEffect ejecuta efectos secundarios (fetch de datos, suscripciones, timers) después del render. Si las dependencias están mal declaradas se producen bucles infinitos o datos desactualizados. El array vacío [] equivale a componentDidMount.

React JSX
// PurchasesPage.jsx — carga inicial al montar el componente
useEffect(() => {
    const loadData = async () => {
        setLoading(true);
        try {
            // Una sola petición trae compras + catálogos
            const res  = await api.get('/compras/init');
            const data = res.data?.data ?? {};
            setPurchases(data.compras      ?? []);
            setSuppliers(data.proveedores  ?? []);
            setProducts(data.productos     ?? []);
            setPayMethods(data.metodos_pago ?? []);
        } catch (err) {
            toast.error('Error al cargar datos');
        } finally {
            setLoading(false);
        }
    };
    loadData();
}, []); // [] = solo al montar; sin array = se ejecuta en CADA render (bucle)
P2.¿Para qué sirve useCallback y en qué situación del proyecto se aplica?

useCallback memoriza una función para que no se recree en cada render. Es útil cuando la función se pasa como prop a un hijo o se incluye en las dependencias de un useEffect. Evita re-renders innecesarios.

React JSX
// Patrón usado en páginas con tabla + modal
// Sin useCallback: handleDelete se recrea en cada render
// -> el hijo que la recibe como prop se re-renderiza también

const handleDelete = useCallback(async (id) => {
    if (!confirm('¿Eliminar este registro?')) return;
    try {
        await productService.remove(id);
        // Actualiza el estado local sin llamar a la API de nuevo
        setProducts(prev => prev.filter(p => p.id !== id));
        toast.success('Producto eliminado');
    } catch {
        toast.error('No se pudo eliminar');
    }
}, []); // sin dependencias: la función siempre es la misma referencia

// El hijo recibe una referencia estable → no se re-renderiza de más
<ProductTable onDelete={handleDelete} />
P3.¿Cómo se maneja el estado de carga y error en una petición async?

Se usan tres estados: loading, data y error. El patrón try/catch/finally garantiza que loading siempre se apague aunque falle la petición.

React JSX
// Patrón estándar en todas las páginas del proyecto
const [products, setProducts]   = useState([]);
const [loading,  setLoading]    = useState(false);
const [error,    setError]      = useState(null);

useEffect(() => {
    const fetchProducts = async () => {
        setLoading(true);
        setError(null);
        try {
            const res = await productService.getAll();
            setProducts(res.data?.data ?? []);
        } catch (err) {
            setError(err.response?.data?.message ?? 'Error inesperado');
            toast.error('No se pudieron cargar los productos');
        } finally {
            setLoading(false); // siempre se ejecuta, haya o no error
        }
    };
    fetchProducts();
}, []);

// En el JSX:
if (loading) return <Spinner />;
if (error)   return <ErrorMessage text={error} />;
return <ProductTable data={products} />;
P4.¿Qué es un componente controlado y cómo se diferencia del no controlado?

En un componente controlado React es la fuente de verdad del valor (via value + onChange). En uno no controlado el DOM maneja el valor y se accede con ref. React Hook Form usa el enfoque no controlado internamente (con ref) para mayor rendimiento.

React JSX
// ── CONTROLADO: React maneja el valor ──────────────────────
const [nombre, setNombre] = useState('');

<input
    value={nombre}
    onChange={(e) => setNombre(e.target.value)}
/>

// ── NO CONTROLADO: React Hook Form (ref interno) ────────────
// register() adjunta una ref al input, NO lo hace controlado
// → mucho mejor rendimiento: no re-renderiza en cada keystroke
const { register, handleSubmit } = useForm();

<input {...register('nombre', { required: 'Nombre obligatorio' })} />

// La diferencia clave:
// Controlado  → re-render en cada tecla  (estado en React)
// No controlado → sin re-renders intermedios (valor en el DOM)
2 · React Router v6 — Rutas y Navegación
P5.¿Cómo está organizado el enrutamiento del proyecto en App.jsx?

Se usa BrowserRouter con rutas anidadas. Las rutas privadas están envueltas en componentes guard. Las rutas públicas (login) redirigen al dashboard si el usuario ya está autenticado.

React JSX
// App.jsx
<BrowserRouter>
  <Routes>
    {/* Ruta pública — redirige si ya está logueado */}
    <Route path="/login" element={
        <PublicRoute><LoginPage /></PublicRoute>
    } />

    {/* Rutas privadas — cualquier usuario autenticado */}
    <Route path="/dashboard" element={
        <PrivateRoute><DashboardPage /></PrivateRoute>
    } />
    <Route path="/productos" element={
        <PrivateRoute><ProductsPage /></PrivateRoute>
    } />

    {/* Rutas solo para admin y super-admin */}
    <Route path="/usuarios" element={
        <AdminRoute><UsersPage /></AdminRoute>
    } />

    {/* Rutas exclusivas de super-admin */}
    <Route path="/auditoria" element={
        <SuperAdminRoute><AuditoriaPage /></SuperAdminRoute>
    } />

    {/* Redirección raíz */}
    <Route path="/" element={<Navigate to="/dashboard" replace />} />
  </Routes>
</BrowserRouter>
P6.¿Cómo se navega programáticamente con useNavigate?

useNavigate retorna una función para navegar sin recargar la página. Se usa después de acciones como login exitoso, logout o al cancelar un formulario.

React JSX
// LoginPage.jsx
import { useNavigate } from 'react-router-dom';

function LoginPage() {
    const navigate = useNavigate();
    const { login } = useAuth();

    const onSubmit = async (data) => {
        try {
            const res = await authService.login(data);
            // Guarda token y user en el contexto + localStorage
            login(res.data.data);
            // Redirige al dashboard después del login exitoso
            navigate('/dashboard', { replace: true });
        } catch (err) {
            toast.error(err.response?.data?.message ?? 'Error de acceso');
        }
    };

    return <form onSubmit={handleSubmit(onSubmit)}>...</form>;
}

// Logout — redirigir al login
const handleLogout = () => {
    logout();                           // limpia contexto + localStorage
    navigate('/login', { replace: true }); // replace: no queda en historial
};

3 · Formularios: React Hook Form + Zod
P8.¿Cómo se integra Zod con React Hook Form para validar un formulario?

Se define un schema Zod y se conecta a useForm mediante zodResolver. La validación ocurre antes de llamar a onSubmit: si algo falla, los errores se muestran en el JSX sin llamar a la API.

React JSX
// schemas/index.js — definición del schema
import { z } from 'zod';

export const productSchema = z.object({
    nombre:       z.string().min(2, 'Mínimo 2 caracteres').max(150),
    descripcion:  z.string().max(500).optional(),
    precio_venta: z.coerce.number().positive('Precio debe ser mayor a 0'),
    precio_compra:z.coerce.number().min(0).optional(),
    stock_minimo: z.coerce.number().int().min(0).default(5),
    categoria_id: z.coerce.number().int().positive('Seleccione una categoría'),
    proveedor_id: z.coerce.number().int().positive('Seleccione un proveedor'),
    codigo:       z.string().max(60).optional(),
    activo:       z.coerce.boolean().default(true),
});

// ProductsPage.jsx — uso en el formulario
import { zodResolver } from '@hookform/resolvers/zod';

const { register, handleSubmit, formState: { errors }, reset } = useForm({
    resolver: zodResolver(productSchema),
    defaultValues: { activo: true, stock_minimo: 5 },
});

// JSX — campo con error
<div>
    <label>Nombre del producto</label>
    <input {...register('nombre')} />
    {errors.nombre &&
        <p className="text-red-500 text-xs mt-1">{errors.nombre.message}</p>
    }
</div>
P9.¿Cómo se pre-cargan datos al abrir un modal de edición?

Se usa reset() de React Hook Form para poblar el formulario con los valores del registro seleccionado. Se llama dentro de un useEffect que observa el registro a editar.

React JSX
// ProductsPage.jsx — modal que sirve para crear Y editar
const { register, handleSubmit, reset, formState: { errors } } = useForm({
    resolver: zodResolver(productSchema),
});

// selectedProduct: null = crear, { id, nombre, ... } = editar
useEffect(() => {
    if (selectedProduct) {
        // Poblamos el formulario con los datos actuales
        reset({
            nombre:       selectedProduct.nombre,
            precio_venta: selectedProduct.precio_venta,
            precio_compra:selectedProduct.precio_compra,
            stock_minimo: selectedProduct.stock_minimo,
            categoria_id: selectedProduct.categoria_id,
            proveedor_id: selectedProduct.proveedor_id,
            codigo:       selectedProduct.codigo ?? '',
            activo:       selectedProduct.activo,
        });
    } else {
        reset({ activo: true, stock_minimo: 5 }); // valores por defecto al crear
    }
}, [selectedProduct, reset]); // se dispara cuando cambia el producto seleccionado

P11.¿Cómo se valida un array de ítems con Zod en el schema de compras?

Se usa z.array() con .min(1) para requerir al menos un ítem, y cada elemento del array tiene su propio objeto de validación.

React JSX
// schemas/index.js — schema de compra con array de ítems
export const purchaseSchema = z.object({
    proveedor_id:   z.coerce.number().int().positive('Seleccione proveedor'),
    metodo_pago_id: z.coerce.number().int().positive('Seleccione método de pago'),
    fecha_compra:   z.string().min(1, 'La fecha es obligatoria'),
    impuesto:       z.coerce.number().min(0).max(100).default(0),
    descuento:      z.coerce.number().min(0).max(100).default(0),
    notas:          z.string().max(500).optional(),

    // Array de ítems — mínimo 1
    items: z.array(z.object({
        product_id:   z.coerce.number().int().positive('Seleccione producto'),
        quantity:     z.coerce.number().int().positive('Cantidad mínima: 1'),
        unit_price:   z.coerce.number().positive('Precio debe ser > 0'),
        discount:     z.coerce.number().min(0).default(0),
    })).min(1, 'Agregue al menos un producto'),
});

// Acceso al error del array:
{errors.items?.root?.message && (
    <p className="text-red-500">{errors.items.root.message}</p>
)}
// Error de un campo específico del ítem i:
{errors.items?.[i]?.unit_price?.message}
4 · Estado Global: AuthContext + useReducer
P12.¿Por qué se eligió useReducer en lugar de useState para el AuthContext?

useReducer es preferible cuando el estado tiene múltiples campos relacionados que cambian juntos (user, token, roles, isAuthenticated). Las acciones nombradas hacen las transiciones explícitas y predecibles, como Redux pero sin dependencias externas.

React JSX
// AuthContext.jsx
// Con useState (PEOR): 4 estados separados que deben cambiar juntos
const [user,            setUser]            = useState(null);
const [token,           setToken]           = useState(null);
const [roles,           setRoles]           = useState([]);
const [isAuthenticated, setIsAuthenticated] = useState(false);
// Problema: si olvidamos actualizar uno, el estado queda inconsistente

// ─────────────────────────────────────────────────────────────
// Con useReducer (MEJOR): un solo estado coherente
const defaultState = { user: null, token: null, roles: [], isAuthenticated: false };

function authReducer(state, action) {
    switch (action.type) {
        case 'LOGIN':
            return {                          // todos los campos a la vez
                user:            action.user,
                token:           action.token,
                roles:           action.roles ?? [],
                isAuthenticated: true,
            };
        case 'LOGOUT':
            return { ...defaultState };       // reset limpio
        case 'UPDATE_USER':
            return { ...state, user: { ...state.user, ...action.payload } };
        default:
            return state;
    }
}

const [state, dispatch] = useReducer(authReducer, defaultState, loadInitialState);
P13.¿Cómo se persiste y recupera la sesión entre recargas de página?

Un useEffect sincroniza el estado con localStorage en cada cambio. La función loadInitialState se pasa como tercer argumento de useReducer para inicializar el estado desde localStorage solo una vez.

React JSX
// AuthContext.jsx

// Función de inicialización lazy — se ejecuta solo una vez al montar
function loadInitialState() {
    try {
        const raw = localStorage.getItem('auth-storage');
        if (!raw) return defaultState;
        const parsed = JSON.parse(raw);
        const data   = parsed.state ?? parsed;

        // Normalizar: si user.rol no existe, derivarlo de roles[0]
        // (compatibilidad con sesiones antiguas)
        if (data?.user && !data.user.rol) {
            const rolDerivado = data.user.roles?.[0] || data.roles?.[0] || null;
            if (rolDerivado) data.user = { ...data.user, rol: rolDerivado };
        }
        return data;
    } catch {
        return defaultState; // si el JSON está corrupto, sesión limpia
    }
}

// useReducer recibe loadInitialState como tercer arg (inicialización lazy)
const [state, dispatch] = useReducer(authReducer, defaultState, loadInitialState);

// Sincronizar con localStorage en cada cambio de estado
useEffect(() => {
    if (state.isAuthenticated) {
        localStorage.setItem('auth-storage', JSON.stringify(state));
    } else {
        localStorage.removeItem('auth-storage');
    }
}, [state]);
P14.¿Cómo se expone el contexto y cómo se consume en un componente?

Se crea un Context, se provee en la raíz con el Provider, y se consume con un hook personalizado useAuth() que lanza un error si se usa fuera del provider.

React JSX
// AuthContext.jsx — crear y exponer
const AuthContext = createContext(null);

export function AuthProvider({ children }) {
    const [state, dispatch] = useReducer(authReducer, defaultState, loadInitialState);

    // Helpers de rol
    const hasRole     = (r) => state.user?.rol === r
                            || state.roles?.includes(r)
                            || state.user?.roles?.includes(r);
    const isSuperAdmin = () => hasRole('super-admin');
    const isAdmin      = () => hasRole('super-admin') || hasRole('admin');

    // Acciones
    const login  = (payload) => dispatch({ type: 'LOGIN',  ...payload });
    const logout = ()         => dispatch({ type: 'LOGOUT' });

    return (
        <AuthContext.Provider value={{ ...state, login, logout, hasRole, isSuperAdmin, isAdmin }}>
            {children}
        </AuthContext.Provider>
    );
}

// Hook personalizado — lanza error si se usa fuera del Provider
export const useAuth = () => {
    const ctx = useContext(AuthContext);
    if (!ctx) throw new Error('useAuth debe usarse dentro de <AuthProvider>');
    return ctx;
};

// Consumo en cualquier componente
const { user, isAdmin, logout } = useAuth();
5 · Comunicación con la API — Axios
P15.¿Cómo está configurada la instancia de Axios y qué hacen sus interceptores?

Se crea una instancia de Axios con la baseURL del backend. El interceptor de request inyecta el token JWT. El interceptor de response maneja automáticamente el error 401 (token expirado).

JavaScript
// services/api.js
import axios from 'axios';

const api = axios.create({
    baseURL: import.meta.env.VITE_API_URL ?? 'http://localhost:8000/api',
    headers: { 'Content-Type': 'application/json', Accept: 'application/json' },
    timeout: 15000, // 15 segundos máximo de espera
});

// ── Interceptor de REQUEST: adjuntar token JWT ──────────────
api.interceptors.request.use((config) => {
    const stored = localStorage.getItem('auth-storage');
    const token  = stored ? JSON.parse(stored).token : null;
    if (token) config.headers.Authorization = `Bearer ${token}`;
    return config;
});

// ── Interceptor de RESPONSE: manejar errores globales ───────
api.interceptors.response.use(
    (response) => response,            // éxito: pasa tal cual
    (error) => {
        if (error.response?.status === 401) {
            // Token expirado o inválido → logout automático
            localStorage.removeItem('auth-storage');
            window.location.href = '/login';
        }
        return Promise.reject(error);  // propaga el error al catch del componente
    }
);

export default api;
P16.¿Cómo funciona el crudService factory y qué ventaja tiene?

Es una función que genera un objeto con todos los métodos CRUD para un endpoint. Se define una vez y se instancia por módulo. Elimina la repetición de escribir las mismas llamadas Axios en cada página.

JavaScript
// services/api.js
const crudService = (endpoint) => ({
    getAll:  (params = {}) => api.get(endpoint, { params }),
    getById: (id)          => api.get(`${endpoint}/${id}`),
    create:  (data)        => api.post(endpoint, data),
    update:  (id, data)    => api.put(`${endpoint}/${id}`, data),
    remove:  (id)          => api.delete(`${endpoint}/${id}`),
    toggle:  (id)          => api.patch(`${endpoint}/${id}/toggle`),
});

// Una línea por módulo — sin repetición
export const productService  = crudService('/productos');
export const clientService   = crudService('/clientes');
export const purchaseService = crudService('/compras');
export const userService     = crudService('/usuarios');
export const categoryService = crudService('/categorias');

// Uso: igual en TODOS los módulos
const list    = await productService.getAll({ search: 'café' });
const created = await productService.create({ nombre: 'Café', precio_venta: 5.5 });
await productService.remove(42);
await productService.toggle(42); // activo/inactivo
P17.¿Cómo se maneja el error de validación 422 que devuelve el backend?

El backend retorna un objeto { status, message, errors } cuando la validación falla. El frontend lo captura en el catch y puede mostrar el mensaje general o los errores de campo específicos.

React JSX
// Patrón de manejo de errores 422 en cualquier formulario
const onSubmit = async (formData) => {
    setSubmitting(true);
    try {
        if (selectedProduct?.id) {
            await productService.update(selectedProduct.id, formData);
            toast.success('Producto actualizado');
        } else {
            await productService.create(formData);
            toast.success('Producto creado');
        }
        closeModal();
        refreshList();
    } catch (err) {
        const status = err.response?.status;
        const data   = err.response?.data;

        if (status === 422) {
            // Errores de validación del backend (Laravel FormRequest)
            const firstError = data?.message ?? 'Error de validación';
            toast.error(firstError);

            // Opcional: mostrar errores de campo individuales
            // data.errors = { nombre: ['El nombre es obligatorio.'], ... }
            if (data?.errors) {
                Object.entries(data.errors).forEach(([field, msgs]) => {
                    setError(field, { message: msgs[0] }); // React Hook Form
                });
            }
        } else {
            toast.error(data?.message ?? 'Error inesperado');
        }
    } finally {
        setSubmitting(false);
    }
};
6 · Protección de Rutas — RouteGuard
P18.¿Cómo están implementados los componentes RouteGuard del proyecto?

Son componentes wrapper que verifican autenticación y rol antes de renderizar a sus hijos. Si no se cumple la condición, redirigen con <Navigate> sin renderizar nada.

React JSX
// RouteGuard.jsx — cuatro guardias del proyecto

// 1. Solo requiere estar logueado
export function PrivateRoute({ children }) {
    const { isAuthenticated } = useAuth();
    if (!isAuthenticated) return <Navigate to="/login" replace />;
    return children;
}

// 2. Solo admin o super-admin
export function AdminRoute({ children }) {
    const { isAuthenticated, isAdmin } = useAuth();
    if (!isAuthenticated) return <Navigate to="/login" replace />;
    if (!isAdmin())       return <Navigate to="/dashboard" replace />;
    return children;
}

// 3. Solo super-admin
export function SuperAdminRoute({ children }) {
    const { isAuthenticated, isSuperAdmin } = useAuth();
    if (!isAuthenticated) return <Navigate to="/login" replace />;
    if (!isSuperAdmin())  return <Navigate to="/dashboard" replace />;
    return children;
}

// 4. Ruta pública: redirige al dashboard si ya está logueado
export function PublicRoute({ children }) {
    const { isAuthenticated } = useAuth();
    if (isAuthenticated) return <Navigate to="/dashboard" replace />;
    return children;
}
P19.¿Cómo se ocultan elementos de la UI según el rol del usuario activo?

// UsersPage.jsx — columna de acciones en la tabla de usuarios

// Un admin solo puede operar sobre NO super-admins

// Columna de acciones

    </div>
) : (
    <span title="Solo el Super Admin puede modificar esta cuenta">—</span>
)}

// Sidebar.jsx — ítems visibles según rol
const itemsVisibles = group.items.filter(
    item => !item.roles || item.roles.some(r => hasRole(r))
);
// Auditoría y Configuración tienen roles: ['super-admin']

P20.¿Cómo se autocompleta el precio al seleccionar un producto en el formulario de compra?

Se reemplaza el onChange nativo del register con un handler personalizado que busca el producto en el catálogo local y llama a setValue para llenar el precio sin disparar una nueva petición al servidor.

React JSX
// PurchaseForm.jsx
const { register, setValue, control } = useForm({ resolver: zodResolver(purchaseSchema) });
const { fields, append, remove }       = useFieldArray({ control, name: 'items' });

// Handler: intercepta el cambio de producto y autocompleta el precio
const handleProductChange = (index, productoId) => {
    // 1. Actualizar el campo product_id en React Hook Form
    setValue(`items.${index}.product_id`, productoId);

    // 2. Buscar en el catálogo local (ya cargado en el estado)
    const producto = products.find(
        p => String(p.id) === String(productoId)
    );

    // 3. Si tiene precio_compra, completar automáticamente
    if (producto && Number(producto.precio_compra) > 0) {
        setValue(`items.${index}.unit_price`, Number(producto.precio_compra));
    }
};

// En el JSX: el select NO usa onChange de register directamente
<select
    {...register(`items.${index}.product_id`)}
    onChange={(e) => handleProductChange(index, e.target.value)}
>
    {products.map(p =>
        <option key={p.id} value={p.id}>
            {p.nombre} — {p.codigo}
        </option>
    )}
</select>
P21.¿Cómo se calcula el total en tiempo real mientras el usuario llena el formulario?

Se usa watch de React Hook Form para observar los campos del formulario y calcular el total derivado. No requiere estado adicional: el total se recalcula en cada render.

React JSX
// PurchaseForm.jsx — total en tiempo real
const { watch } = useForm({ resolver: zodResolver(purchaseSchema) });

// Observar todos los campos relevantes
const watchedItems     = watch('items')     ?? [];
const watchedImpuesto  = watch('impuesto')  ?? 0;
const watchedDescuento = watch('descuento') ?? 0;

// Calcular subtotal sumando líneas
const subtotal = watchedItems.reduce((acc, item) => {
    const cant      = Number(item?.quantity    ?? 0);
    const precio    = Number(item?.unit_price  ?? 0);
    const descLinea = Number(item?.discount    ?? 0);
    return acc + (cant * precio) - descLinea;
}, 0);

const montoDescuento  = subtotal * (Number(watchedDescuento) / 100);
const base            = subtotal - montoDescuento;
const montoImpuesto   = base     * (Number(watchedImpuesto)  / 100);
const total           = base + montoImpuesto;

// En el JSX — se actualiza automáticamente sin botón
<div className="text-right text-xl font-bold">
    Total: S/ {total.toFixed(2)}
</div>
P22.¿Cómo se maneja el flujo de estados de una compra (pendiente → recibida) en el frontend?

Cada acción (confirmar, recibir, anular, retroceder) llama a su propio endpoint. El estado local se actualiza con el objeto retornado por el backend, reflejando el nuevo estado sin recargar toda la lista.

React JSX
// PurchasesPage.jsx — acciones de transición de estado
const handleConfirmar = async (id) => {
    try {
        const res = await api.post(`/compras/${id}/confirmar`);
        // Actualizar solo la compra afectada en el estado local
        setPurchases(prev =>
            prev.map(c => c.id === id ? res.data.data : c)
        );
        toast.success('Compra confirmada');
    } catch (err) {
        toast.error(err.response?.data?.message ?? 'Error al confirmar');
    }
};

// En el JSX — mostrar botones según el estado actual
const getAcciones = (compra) => {
    switch (compra.estado) {
        case 'pendiente':
            return [
                <button onClick={() => handleConfirmar(compra.id)}>Confirmar</button>,
                <button onClick={() => handleAnular(compra.id)}>Anular</button>,
            ];
        case 'confirmada':
            return [
                <button onClick={() => handleRecibir(compra.id)}>Recibir</button>,
                <button onClick={() => handleAnular(compra.id)}>Anular</button>,
            ];
        case 'recibida':
            return [<span className="text-green-600">✓ Recibida</span>];
        case 'anulada':
            return [<span className="text-red-400">Anulada</span>];
    }
};

P23.¿Cómo se gestiona el carrito de ventas en el estado del POS?

El carrito es un array en el estado local. Al agregar un producto se verifica si ya existe para incrementar la cantidad. Al quitar se filtra por ID. El total se calcula derivado del carrito.

React JSX
// PosScreen.jsx — gestión del carrito
const [cart, setCart] = useState([]);

// Agregar producto al carrito (o incrementar cantidad si ya existe)
const addToCart = (producto) => {
    setCart(prev => {
        const exists = prev.find(i => i.id === producto.id);
        if (exists) {
            // Incrementar cantidad
            return prev.map(i =>
                i.id === producto.id
                    ? { ...i, cantidad: i.cantidad + 1 }
                    : i
            );
        }
        // Nuevo ítem en el carrito
        return [...prev, { ...producto, cantidad: 1, descuento: 0 }];
    });
};

// Quitar producto del carrito
const removeFromCart = (id) =>
    setCart(prev => prev.filter(i => i.id !== id));

// Actualizar cantidad manualmente
const updateQuantity = (id, cantidad) =>
    setCart(prev => prev.map(i => i.id === id ? { ...i, cantidad } : i));

// Total derivado — calculado en cada render sin estado extra
const subtotal = cart.reduce(
    (sum, item) => sum + (item.precio_venta * item.cantidad) - item.descuento, 0
);

P24.¿Cómo se buscan y filtran productos en tiempo real en el POS?

Se usa un estado de búsqueda y useMemo para filtrar la lista de productos sin re-procesar en cada render. El filtro aplica sobre nombre y código del producto.

React JSX
// PosScreen.jsx — búsqueda de productos en tiempo real
const [products,    setProducts]    = useState([]);
const [searchTerm,  setSearchTerm]  = useState('');
const [selectedCat, setSelectedCat] = useState(null);

// useMemo: solo recalcula cuando cambian products, searchTerm o selectedCat
const filteredProducts = useMemo(() => {
    let list = products.filter(p => p.activo && p.stock > 0);

    // Filtrar por categoría si hay una seleccionada
    if (selectedCat) {
        list = list.filter(p => p.categoria_id === selectedCat);
    }

    // Filtrar por término de búsqueda (nombre o código)

        const term = searchTerm.toLowerCase();

            p.nombre.toLowerCase().includes(term) ||
            p.codigo?.toLowerCase().includes(term)

    }

    return list;
}, [products, searchTerm, selectedCat]);

P25.¿Cómo se aplican promociones automáticamente al carrito?

Al cargar el POS se obtienen las promociones activas. Cuando el carrito cambia, se evalúa cuáles aplican según el tipo (porcentaje, monto fijo, 2x1) y se aplica el mejor descuento disponible.

React JSX
// PosScreen.jsx — aplicar promoción al procesar la venta
const [promotions,       setPromotions]       = useState([]);
const [appliedPromotion, setAppliedPromotion] = useState(null);

// Calcular descuento según tipo de promoción
const calcularDescuentoPromocion = (promo, subtotal) => {
    switch (promo.tipo) {
        case 'porcentaje':
            return subtotal * (promo.valor / 100);
        case 'monto_fijo':
            return Math.min(promo.valor, subtotal); // no puede ser mayor al subtotal
        case 'envio_gratis':
            return 0; // el descuento en envío se maneja aparte
        default:
            return 0;
    }
};

// Verificar si una promoción aplica al carrito actual
const promoAplica = (promo) => {
    // Debe estar activa y en rango de fechas
    if (!promo.activo) return false;
    const hoy = new Date();
    if (promo.fecha_inicio && new Date(promo.fecha_inicio) > hoy) return false;
    if (promo.fecha_fin    && new Date(promo.fecha_fin)    < hoy) return false;
    // El subtotal debe superar el mínimo requerido
    if (promo.minimo_compra && subtotal < promo.minimo_compra) return false;
    return true;
};

P26.¿Cómo se evita que el usuario haga clic doble en el botón de submit?

P28.¿Cómo se actualiza un ítem en el estado local sin recargar toda la lista desde la API?

Se usa setState(prev => prev.map(...)) para reemplazar solo el ítem afectado con la respuesta del backend. Esto evita una nueva petición GET y hace la UI más rápida.

React JSX
// Patrón "actualización optimista / por respuesta" — usado en todo el proyecto

// ── Al editar: reemplazar el ítem con la respuesta del backend ──
const handleUpdate = async (id, formData) => {
    try {
        const res = await productService.update(id, formData);
        const updated = res.data?.data;

        // Solo actualiza el ítem modificado, no recarga toda la lista
        setProducts(prev =>
            prev.map(p => p.id === id ? updated : p)
        );
        toast.success('Producto actualizado');
        closeModal();
    } catch (err) {
        toast.error(err.response?.data?.message ?? 'Error al actualizar');
    }
};

// ── Al toggle activo/inactivo: invertir el campo booleano ──
const handleToggle = async (id) => {
    try {
        const res = await productService.toggle(id);
        setProducts(prev =>
            prev.map(p => p.id === id ? { ...p, activo: !p.activo } : p)
        );
    } catch { toast.error('Error al cambiar estado'); }
};

// ── Al crear: agregar al inicio del array ──
const handleCreate = async (formData) => {
    const res     = await productService.create(formData);
    const created = res.data?.data;
    setProducts(prev => [created, ...prev]); // al inicio = orden más reciente
};
