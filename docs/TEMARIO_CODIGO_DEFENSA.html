1 · Autenticación JWT
P1.¿Cómo se realiza el login y qué devuelve el backend?

El controlador valida credenciales con el guard 'api' de JWT. Si son correctas y el usuario está activo, genera un token y lo retorna junto con los datos del usuario, sus roles y permisos.

PHP
// AuthenticationController.php
$credentials = [
    'usuario'  => $request->validated('usuario'),
    'password' => $request->input('password'),
];

if (! $token = auth('api')->attempt($credentials)) {
    RateLimiter::hit('login:' . $request->ip(), 60);
    return response()->json(['status' => false,
        'message' => 'Credenciales invalidas.'], 401);
}

$usuario = auth('api')->user();
if (!$usuario->activo) {
    auth('api')->logout();
    return response()->json(['status' => false,
        'message' => 'Usuario inactivo.'], 403);
}

return response()->json([
    'access_token' => $token,
    'token_type'   => 'bearer',
    'user'         => new UsuarioResource($usuario),
    'roles'        => $usuario->getRoleNames(),
    'permissions'  => $usuario->getAllPermissions()->pluck('name'),
]);
P2.¿Cómo envía el frontend el token JWT en cada petición?

Un interceptor de Axios lee el token desde localStorage y lo añade automáticamente en el header Authorization de cada request, sin necesidad de hacerlo manualmente en cada llamada. Si el token expira (401), limpia la sesión y redirige al login.

JavaScript
// services/api.js
api.interceptors.request.use((config) => {
    const stored = localStorage.getItem('auth-storage');
    const token  = stored ? JSON.parse(stored).token : null;
    if (token) {
        config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
});

// Interceptor de respuesta: si el token expira (401) -> logout automático
api.interceptors.response.use(
    (response) => response,
    (error) => {
        if (error.response?.status === 401) {
            localStorage.removeItem('auth-storage');
            window.location.href = '/login';
        }
        return Promise.reject(error);
    }
);
P3.¿Cómo se protege el login contra ataques de fuerza bruta?

Se usa el RateLimiter de Laravel para bloquear una IP que supere 5 intentos fallidos durante 60 segundos, retornando HTTP 429.

PHP
// AuthenticationController.php
$key = 'login:' . $request->ip();

if (RateLimiter::tooManyAttempts($key, 5)) {
    $seconds = RateLimiter::availableIn($key);
    return response()->json([
        'message' => "Demasiados intentos. Intente en {$seconds}s.",
    ], 429);  // HTTP 429 Too Many Requests
}

// Si las credenciales son incorrectas, penalizar el intento
if (! $token = auth('api')->attempt($credentials)) {
    RateLimiter::hit($key, 60);  // ventana de 60 segundos
    return response()->json(['message' => 'Credenciales invalidas.'], 401);
}

RateLimiter::clear($key);  // éxito: limpiar conteo
2 · Roles y Permisos (Spatie)
P4.¿Cómo se protegen las rutas por rol en el backend?

El middleware de Spatie 'role' se aplica en grupos de rutas en api.php. Si el usuario no tiene el rol requerido, retorna 403 automáticamente.

PHP
// routes/api.php

// Solo super-admin puede ver auditoría y configuración
Route::middleware(['auth:api', 'role:super-admin'])->group(function () {
    Route::get('/auditoria', [AuditoriaController::class, 'index']);
    Route::get('/configuracion/empresa', [EmpresaController::class, 'show']);
});

// Admin y super-admin pueden gestionar usuarios
Route::middleware(['auth:api', 'role:super-admin|admin'])->group(function () {
    Route::get('/usuarios',        [UserController::class, 'index']);
    Route::post('/usuarios',       [UserController::class, 'createUser']);
    Route::put('/usuarios/{i}',    [UserController::class, 'update']);
    Route::delete('/usuarios/{i}', [UserController::class, 'destroy']);
});
P5.¿Cómo se bloquea que el admin edite o elimine al super-admin?

En cada método del UserController (update, destroy, toggleActivo) se verifica: si el usuario objetivo es super-admin Y el usuario autenticado NO es super-admin, se rechaza con 403.

PHP
// UserController.php — método update()
public function update(UsuarioUpdateRequest $request, int $id)
{
    $usuario = Usuario::findOrFail($id);

    // Admin no puede modificar cuentas super-admin
    // Solo otro super-admin puede hacerlo
    if ($usuario->hasRole('super-admin')
        && !auth('api')->user()->hasRole('super-admin')) {
        return $this->error(
            'No tienes permiso para editar a un Super Admin.', 403
        );
    }

    // ... continúa con la actualización
}
P6.¿Cómo se ocultan módulos en el Sidebar según el rol del usuario?

Cada ítem de navegación declara los roles que lo pueden ver. Al renderizar, se filtra con hasRole() del AuthContext. Si el usuario no tiene el rol, el ítem no se renderiza en el DOM.

React JSX
// Sidebar.jsx — definición de navegación
const navGroups = [{
    label: 'Sistema',
    items: [
        { to: '/usuarios',  roles: ['super-admin', 'admin'] },
        { to: '/auditoria', roles: ['super-admin'] },  // solo SA
        { to: '/config',    roles: ['super-admin'] },  // solo SA
    ],
}];

// Filtrado al renderizar
const itemsVisibles = group.items.filter(
    item => item.roles.some(r => hasRole(r))
);

// hasRole() en AuthContext
const hasRole = (r) => {
    return state.user?.rol === r
        || state.roles?.includes(r)
        || state.user?.roles?.includes(r);
};
P7.¿Cómo se protegen las rutas en el frontend con RouteGuard?

3 · Validaciones Backend y Frontend
P8.¿Cómo funciona un FormRequest en Laravel?

Clase que encapsula las reglas de validación fuera del controlador. Si falla, lanza automáticamente una HttpResponseException con status 422 y los errores en JSON.

PHP
// UsuarioCreateRequest.php
public function rules(): array
{
    return [
        'nombre'   => 'required|string|min:2|max:100',
        'usuario'  => [
            'required', 'string',
            Rule::unique('usuarios', 'usuario'),
            'regex:/^[a-zA-Z0-9_-]+$/',
        ],
        'password' => 'required|string|min:8|confirmed',
        'rol'      => 'required|string|in:admin,vendedor',
    ];
}

// Respuesta personalizada cuando falla la validación
protected function failedValidation(Validator $validator): void
{
    throw new HttpResponseException(response()->json([
        'status'  => false,
        'message' => $validator->errors()->first(),
        'errors'  => $validator->errors(),
    ], 422));
}

P10.¿Cómo se valida unicidad ignorando el registro actual al editar?

En el FormRequest de update se usa Rule::unique()->ignore() con el ID del registro que se está editando, para que no genere error de duplicado consigo mismo.

PHP
// UsuarioUpdateRequest.php
public function rules(): array
{
    // El parámetro de ruta en api.php es '{i}'
    $userId = $this->route('i');

    return [
        'usuario' => [
            'required', 'string',
            // Ignora el mismo registro al verificar unicidad
            Rule::unique('usuarios', 'usuario')->ignore($userId, 'id'),
        ],
        'correo' => [
            'nullable', 'email',
            // La columna en BD es 'email', no 'correo'
            Rule::unique('usuarios', 'email')->ignore($userId, 'id'),
        ],
    ];
}
4 · Eloquent ORM y Base de Datos
P11.¿Cómo se evita el problema N+1 con Eager Loading?

Se usa with() para cargar relaciones en una sola query adicional, en lugar de disparar una query por cada registro del loop (N+1 queries).

PHP
// SIN eager loading — N+1 queries (MAL)
$compras = Compra::all();          // 1 query
foreach ($compras as $c) {
    echo $c->proveedor->nombre;    // 1 query POR compra = N queries
}

// CON eager loading — 2 queries total (BIEN)
$compras = Compra::with('proveedor')->get();
// Query 1: SELECT * FROM compras
// Query 2: SELECT * FROM proveedores WHERE id IN (1,2,3...)

// Carga anidada (compra -> detalles -> producto de cada detalle)
$compra = Compra::with('detalles.producto')->findOrFail($id);
// Solo 3 queries, sin importar cuántos detalles tenga la compra
P12.¿Cómo funciona una transacción de base de datos en el proyecto?

DB::transaction() agrupa operaciones en una unidad atómica. Si cualquier operación lanza una excepción, todas las anteriores se revierten automáticamente (rollback).

PHP
// CompraController.php — recibir compra
DB::transaction(function () use ($compra) {
    $now = now();
    foreach ($compra->detalles as $detalle) {
        // UPDATE directo: suma stock + actualiza precio en una sola query
        DB::table('productos')
            ->where('id', $detalle->producto_id)
            ->whereNull('deleted_at')
            ->update([
                'stock'         => DB::raw("stock + {$detalle->cantidad}"),
                'precio_compra' => $detalle->precio_unitario,
                'updated_at'    => $now,
            ]);
    }
    // Si este update falla, el stock tampoco cambia (rollback automático)
    $compra->update(['estado' => 'recibida', 'fecha_recepcion' => $now]);
});

// Cache solo se invalida UNA VEZ, fuera de la transacción
(new Producto)->invalidateCache(['productos', 'pos', 'dashboard']);
P13.¿Qué son los Scopes de Eloquent y cómo se usan?

Los scopes son filtros reutilizables definidos en el modelo que permiten encadenar condiciones de consulta de forma legible y sin repetir código.

PHP
// Producto.php — definición de scopes
public function scopeActivo($query)
{
    return $query->where('activo', true);
}

public function scopeStockBajo($query)
{
    // Productos cuyo stock está en o por debajo del mínimo
    return $query->whereColumn('stock', '<=', 'stock_minimo');
}

// Uso encadenado en el controlador
$productos = Producto::activo()
    ->stockBajo()
    ->orderBy('stock', 'asc')
    ->get();

// Equivale a:
// SELECT * FROM productos
// WHERE activo = true AND stock <= stock_minimo
// ORDER BY stock ASC
P14.¿Cómo funciona SoftDeletes en este proyecto?

En lugar de borrar físicamente, Eloquent añade una marca de tiempo en deleted_at. Las queries normales excluyen esos registros automáticamente con WHERE deleted_at IS NULL.

PHP
// Producto.php
use Illuminate\Database\Eloquent\SoftDeletes;
class Producto extends Model {
    use SoftDeletes; // habilita la columna deleted_at
}

// Query normal — excluye eliminados (WHERE deleted_at IS NULL)
Producto::where('activo', true)->get();

// Para incluir eliminados
Producto::withTrashed()->get();

// Para ver solo los eliminados
Producto::onlyTrashed()->get();

// En CompraController: el UPDATE respeta soft deletes
DB::table('productos')
    ->where('id', $detalle->producto_id)
    ->whereNull('deleted_at')  // no tocar productos eliminados
    ->update(['stock' => DB::raw("stock + {$detalle->cantidad}")]);
5 · Sistema de Caché
P15.¿Cómo funciona el middleware CacheApiResponse?

Intercepta los GET, construye una clave versionada y devuelve la respuesta guardada si existe (HIT). Si no (MISS), pasa al controlador y guarda la respuesta para la próxima vez. Agrega headers X-Cache: HIT/MISS.

PHP
// CacheApiResponse.php — flujo simplificado
public function handle(Request $request, Closure $next): Response
{
    if (! $request->isMethod('GET')) return $next($request);

    $module  = $this->extractModule($request->path()); // 'productos'
    $version = (int) Cache::get("cache_ver:{$module}", 1);
    $urlHash = hash('sha256', $request->fullUrl());
    $key     = "api_resp:{$module}:v{$version}:{$urlHash}";

    if (Cache::has($key)) {
        $cached = Cache::get($key);
        return response($cached['body'], 200)
            ->header('X-Cache', 'HIT');   // respuesta instantánea
    }

    $response = $next($request);          // va al controlador
    if ($response->getStatusCode() === 200) {
        Cache::put($key, [                // guarda para próxima vez
            'body'   => $response->getContent(),
            'status' => 200,
        ], $ttl);
    }
    return $response->header('X-Cache', 'MISS');
}
P16.¿Cómo se invalida el caché automáticamente cuando cambia un modelo?

El trait HasApiCache escucha los eventos Eloquent (saved, deleted) e incrementa un contador de versión. La clave vieja queda "huérfana" y el middleware nunca la encontrará.

PHP
// HasApiCache.php
protected static function bootHasApiCache(): void
{
    $bumpVersion = static function ($model): void {
        foreach ($model->resolveCacheModules() as $module) {
            // Incrementa la versión: v1 -> v2 -> v3...
            // Las claves con v1 y v2 quedan huérfanas y expiran por TTL
            Cache::increment("cache_ver:{$module}");
        }
    };

    static::saved($bumpVersion);   // onCreate + onUpdate
    static::deleted($bumpVersion); // onDelete (incluye soft delete)
}

// Producto.php — módulos que se invalidan al cambiar un producto
protected array $cacheModules = ['productos', 'dashboard'];

// Invalidación manual (cuando DB::table no dispara eventos Eloquent)
(new Producto)->invalidateCache(['productos', 'pos', 'dashboard', 'compras']);
6 · Estado Global (Context API + useReducer)
P17.¿Cómo funciona el AuthContext con useReducer?

useReducer gestiona las transiciones de estado de autenticación. Las acciones (LOGIN, LOGOUT, UPDATE_USER) definen cómo cambia el estado de forma predecible. Un useEffect sincroniza con localStorage.

React JSX
// AuthContext.jsx
function authReducer(state, action) {
    switch (action.type) {
        case 'LOGIN':
            return {
                user:            action.user,
                token:           action.token,
                roles:           action.roles ?? [],
                isAuthenticated: true,
            };
        case 'LOGOUT':
            return { ...defaultState }; // limpia todo
        case 'UPDATE_USER':
            // Actualiza parcialmente el usuario (ej: edición de perfil)
            return { ...state, user: { ...state.user, ...action.payload } };
        default: return state;
    }
}

// useEffect sincroniza con localStorage en cada cambio de estado
useEffect(() => {
    if (state.isAuthenticated) {
        localStorage.setItem('auth-storage', JSON.stringify(state));
    } else {
        localStorage.removeItem('auth-storage'); // limpia al logout
    }
}, [state]);
P18.¿Cómo se consume el AuthContext en un componente?

Con el hook useAuth() que expone el estado y los helpers de rol. Cualquier componente del árbol puede acceder sin prop-drilling.

React JSX

7 · Servicios y Comunicación con la API
P19.¿Qué es el crudService factory y cómo evita repetición de código?

Una función que genera un objeto de servicios CRUD reutilizable para cualquier endpoint. Se define una vez y se instancia por módulo, evitando duplicar las mismas llamadas HTTP.

JavaScript
// services/api.js
const crudService = (endpoint) => ({
    getAll:  (params)    => api.get(endpoint, { params }),
    getById: (id)        => api.get(`${endpoint}/${id}`),
    create:  (data)      => api.post(endpoint, data),
    update:  (id, data)  => api.put(`${endpoint}/${id}`, data),
    remove:  (id)        => api.delete(`${endpoint}/${id}`),
    toggle:  (id)        => api.patch(`${endpoint}/${id}/toggle`),
});

// Se instancia una vez por módulo
export const productService  = crudService('/productos');
export const clientService   = crudService('/clientes');
export const purchaseService = crudService('/compras');
export const userService     = crudService('/usuarios');

// Uso en un componente
const res = await productService.create(data);  // POST /productos
await productService.toggle(id);                // PATCH /productos/5/toggle
P20.¿Qué hace el endpoint /init y por qué se usa?

Agrupa en una sola request todos los datos que necesita una página al cargar (lista principal + catálogos del formulario), reduciendo el número de round-trips al servidor de ~4 requests a solo 1.

PHP
// CompraController.php
public function init(): JsonResponse
{
    $compras     = Compra::with(['proveedor','metodoPago','usuario'])
                        ->orderBy('fecha_compra','desc')->get();
    $proveedores = Proveedor::where('activo', true)->orderBy('nombre')
                           ->get(['id','nombre','razon_social']);
    $productos   = Producto::where('activo', true)->orderBy('nombre')
                          ->get(['id','nombre','codigo','precio_compra']);
    $metodosPago = MetodoPago::where('activo', true)->get();

    return $this->success([
        'compras'      => CompraResource::collection($compras),
        'proveedores'  => ProveedorResource::collection($proveedores),
        'productos'    => $productos->map(fn($p) => [
            'id'            => $p->id,
            'nombre'        => $p->nombre,
            'precio_compra' => (float) $p->precio_compra,
        ]),
        'metodos_pago' => MetodoPagoResource::collection($metodosPago),
    ]);
}

// Frontend: una sola llamada al cargar la página
const res  = await api.get('/compras/init');
const data = res.data?.data ?? {};
setPurchases(data.compras ?? []);
setProducts(data.productos ?? []);

P22.¿Por qué el código de producto se autogenera si no se ingresa?

El frontend trata codigo como opcional. El backend detecta si viene vacío, inserta un temporal único para cumplir la restricción NOT NULL, y luego lo reemplaza con PROD-{id} usando el ID autogenerado.

PHP
// ProductoController.php — store()

if ($codigoEsAutogenerado) {
    // Temporal único: evita error NOT NULL/UNIQUE en el INSERT
    $data['codigo'] = 'TMP-' . uniqid();
}

$producto = Producto::create($data);

// Reemplazar temporal con código definitivo basado en el ID
if ($codigoEsAutogenerado) {
    $codigoFinal = 'PROD-' . str_pad($producto->id, 4, '0', STR_PAD_LEFT);
    $producto->update(['codigo' => $codigoFinal]);
    // Resultado: PROD-0001, PROD-0042, PROD-0100...
}

P23.¿Cómo se calcula el total de una compra en el backend?

Se itera sobre los ítems sumando subtotales por línea, luego se aplica descuento porcentual global e impuesto sobre la base resultante.

PHP
// CompraController.php — store()
$subtotal  = 0;
$impuesto  = (float) ($data['impuesto']  ?? 0); // porcentaje ej: 12
$descuento = (float) ($data['descuento'] ?? 0); // porcentaje ej: 5

foreach ($data['items'] as $item) {
    $lineSubtotal = ($item['cantidad'] * $item['precio_unitario'])
                  - ($item['descuento'] ?? 0);
    $subtotal    += $lineSubtotal;
}

// Descuento global (% sobre subtotal)
$montoDescuento = $descuento > 0
    ? round($subtotal * ($descuento / 100), 2)
    : 0;

$base          = $subtotal - $montoDescuento;
$montoImpuesto = $impuesto > 0
    ? round($base * ($impuesto / 100), 2)
    : 0;

$total = $base + $montoImpuesto;
P24.¿Cómo funciona el trait ApiResponse para estandarizar respuestas?

Centraliza el formato JSON de todas las respuestas del sistema. El frontend siempre encuentra los datos en la misma estructura ({ status, message, data }) independientemente del endpoint.

PHP
// Trait ApiResponse.php (en Controller base)
protected function success(
    mixed  $data    = null,
    string $message = 'OK',
    int    $status  = 200,
    array  $meta    = []
): JsonResponse {
    $response = ['status' => true, 'message' => $message];
    if ($data !== null) $response['data'] = $data;
    if (!empty($meta))  $response = array_merge($response, $meta);
    return response()->json($response, $status);
}

protected function error(string $message, int $status = 500): JsonResponse
{
    return response()->json(['status' => false, 'message' => $message], $status);
}

// Frontend siempre accede igual:
const res      = await productService.getAll();
const productos = res.data?.data ?? [];  // siempre 'response.data.data'
9 · Auditoría y Migraciones
P25.¿Cómo registra cambios automáticamente el trait Auditable?

Escucha los eventos Eloquent (created, updated, deleted) y guarda un registro en auditoria_logs con el modelo, ID, acción, usuario e IP. Basta con usar el trait en el modelo.

PHP
// Auditable.php
protected static function bootAuditable(): void
{
    $log = static function ($model, string $accion): void {
        AuditoriaLog::create([
            'modelo'     => class_basename($model), // 'Producto'
            'modelo_id'  => $model->getKey(),
            'accion'     => $accion,               // 'created'
            'usuario_id' => auth('api')->id(),
            'ip'         => request()->ip(),
            'user_agent' => request()->userAgent(),
        ]);
    };

    static::created(fn($m)  => $log($m, 'created'));
    static::updated(fn($m)  => $log($m, 'updated'));
    static::deleted(fn($m)  => $log($m, 'deleted'));
}

// Uso: simplemente agregar el trait al modelo
class Producto extends Model {
    use Auditable; // ya registra todo automáticamente
}
P26.¿Cómo se crea y revierte una migración?

Las migraciones definen up() para aplicar cambios y down() para revertirlos. Esto permite reproducir la BD en cualquier entorno y hacer rollback si algo sale mal.

PHP
// 2026_05_26_make_codigo_nullable_in_productos_table.php
public function up(): void
{
    Schema::table('productos', function (Blueprint $table) {
        // Solo cambia nullability — el índice unique ya existe
        $table->string('codigo', 60)->nullable()->change();
    });
}

public function down(): void
{
    Schema::table('productos', function (Blueprint $table) {
        $table->string('codigo', 60)->nullable(false)->change();
    });
}

// Comandos esenciales
php artisan migrate          // aplica todas las migraciones pendientes
php artisan migrate:rollback  // revierte la última tanda
php artisan migrate:status    // muestra el estado de cada migración
php artisan migrate:fresh     // borra todo y vuelve a migrar (solo dev)
